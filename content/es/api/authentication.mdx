# Autenticación

La API Pública de Janovix (`api.janovix.com`) utiliza **llaves de API con alcance de organización** para la autenticación. Las llaves de API son el único método de autenticación soportado para integraciones de terceros.

<Callout type="info">
	**Flujo interno de JWT:** El gateway intercambia tu llave de API por un JWT de
	corta duración (30–60 s) en cada solicitud y lo reenvía al servicio AML. Este
	proceso es completamente transparente — tú solo interactúas con tu llave
	`sk_live_...`.
</Callout>

## Crear una Llave de API

Crea llaves de API en **[auth.janovix.com/settings](https://auth.janovix.com/settings) → API Keys**. Consulta la [guía de configuración de API Keys](/es/settings/api-keys) para instrucciones completas.

Formato de la llave: `sk_live_` seguido de una cadena aleatoria.

<Callout type="error">
	**El valor completo de la llave se muestra solo una vez** — al momento de
	crearla. Cópiala de inmediato y guárdala en un administrador de secretos (AWS
	Secrets Manager, HashiCorp Vault, Cloudflare Secrets, etc.). Nunca incluyas
	llaves de API en repositorios de código fuente.
</Callout>

## Usar tu Llave de API

Incluye la llave en el encabezado `Authorization` de cada solicitud como token Bearer:

```http
GET https://api.janovix.com/api/v1/clients
Authorization: Bearer sk_live_your_api_key_here
Content-Type: application/json
```

async function janovixFetch<T>(
path: string,
options: RequestInit = {}
): Promise<T> {
const res = await fetch(`${BASE_URL}${path}`, {

},
});

}

}

import os
import requests

BASE_URL = "https://api.janovix.com/api/v1"

session = requests.Session()
session.headers.update({
    "Authorization": f"Bearer {os.environ['JANOVIX_API_KEY']}",
    "Content-Type": "application/json",
})

def api_get(path: str, **params) -> dict:
    res = session.get(f"{BASE_URL}{path}", params=params)
    res.raise_for_status()
    return res.json()

def api_post(path: str, body: dict) -> dict:
    res = session.post(f"{BASE_URL}{path}", json=body)
    res.raise_for_status()
    return res.json()

# Uso

require "net/http"
require "json"
require "uri"

BASE_URL = "https://api.janovix.com/api/v1"
API_KEY = ENV.fetch("JANOVIX_API_KEY")

def janovix_request(method, path, body: nil)
uri = URI("#{BASE_URL}#{path}")
klass = { "GET" => Net::HTTP::Get, "POST" => Net::HTTP::Post,
"PUT" => Net::HTTP::Put, "PATCH" => Net::HTTP::Patch,

req["Authorization"] = "Bearer #{API_KEY}"
req["Content-Type"] = "application/json"
req.body = body.to_json if body

Net::HTTP.start(uri.hostname, uri.port, use_ssl: true) { |h| h.request(req) }
.then { |res| JSON.parse(res.body) }
end

# Uso

clients = janovix_request("GET", "/clients")["data"]

```php
<?php
define('JANOVIX_BASE_URL', 'https://api.janovix.com/api/v1');
define('JANOVIX_API_KEY', getenv('JANOVIX_API_KEY'));

function janovix_request(string $method, string $path, ?array $body = null): array {
    $ch = curl_init(JANOVIX_BASE_URL . $path);
    $headers = [
        'Authorization: Bearer ' . JANOVIX_API_KEY,
        'Content-Type: application/json',
    ];
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_CUSTOMREQUEST  => $method,
        CURLOPT_HTTPHEADER     => $headers,
        CURLOPT_POSTFIELDS     => $body ? json_encode($body) : null,
    ]);
    $response = curl_exec($ch);
    $code = curl_getinfo($ch, CURLINFO_HTTP_CODE);
    curl_close($ch);
    if ($code >= 400) {
        throw new RuntimeException("API error {$code}: {$response}");
    }
    return json_decode($response, true);
}

// Uso
$clients = janovix_request('GET', '/clients')['data'];
````

## Errores de Autenticación

| Código HTTP | Error                                                 | Causa                                             |
| ----------- | ----------------------------------------------------- | ------------------------------------------------- |
| `401`       | `Missing API key.`                                    | No hay encabezado `Authorization` o token Bearer  |
| `401`       | `Invalid API key.`                                    | Llave no encontrada en el sistema                 |
| `401`       | `Invalid API key format.`                             | Cadena de llave con formato incorrecto            |
| `403`       | `This API key has been revoked.`                      | La llave fue revocada en Configuración            |
| `403`       | `This API key has expired.`                           | La llave superó su fecha de expiración            |
| `403`       | `Your subscription plan does not include API access.` | El plan debe ser Pro o Ultra para acceso a la API |
| `503`       | `Authentication service unavailable.`                 | Transitorio — reintenta con retroceso exponencial |

## Requisitos de Plan

El acceso a la API requiere una suscripción **Pro** o **Ultra**. Las organizaciones con plan Business recibirán un `403` al intentar usar la API. Actualiza tu plan en [Configuración → Facturación](/es/settings/billing).

## Mejores Prácticas

| Práctica                        | Recomendación                                                                                       |
| ------------------------------- | --------------------------------------------------------------------------------------------------- |
| **Solo en el servidor**         | Nunca incluyas llaves de API en JavaScript del navegador, apps móviles ni código del lado cliente   |
| **Una llave por integración**   | Crea una llave dedicada por sistema para poder revocar una sin afectar las demás                    |
| **Usa variables de entorno**    | Guarda las llaves en variables de entorno o un administrador de secretos, nunca en el código fuente |
| **Rota regularmente**           | Rota las llaves de API cada 90 días como práctica de higiene de seguridad                           |
| **Monitorea el último uso**     | Revoca llaves que no se hayan usado en más de 90 días (visible en Configuración → API Keys)         |
| **Maneja el 503 correctamente** | El gateway o el servicio puede estar temporalmente no disponible — implementa retroceso exponencial |
