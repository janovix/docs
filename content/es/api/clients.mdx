# API de Clientes

La API de Clientes gestiona el registro de clientes asociados a operaciones de actividades vulnerables.

**Ruta base:** `/api/v1/clients`

## Endpoints

| Método   | Ruta                      | Descripción                           |
| -------- | ------------------------- | ------------------------------------- |
| `GET`    | `/clients`                | Listar clientes (paginado, filtrable) |
| `GET`    | `/clients/stats`          | Estadísticas agregadas                |
| `GET`    | `/clients/:id`            | Obtener un cliente                    |
| `GET`    | `/clients/:id/kyc-status` | Obtener estado de cumplimiento KYC    |
| `POST`   | `/clients`                | Crear un cliente                      |
| `PUT`    | `/clients/:id`            | Actualización completa                |
| `PATCH`  | `/clients/:id`            | Actualización parcial                 |
| `DELETE` | `/clients/:id`            | Eliminación lógica                    |

def janovix_post(path, body)
  uri = URI("#{BASE_URL}#{path}")
  req = Net::HTTP::Post.new(uri)
  req["Authorization"] = "Bearer #{API_KEY}"
  req["Content-Type"]  = "application/json"
  req.body = body.to_json
  res = Net::HTTP.start(uri.hostname, uri.port, use_ssl: true) { |h| h.request(req) }
  JSON.parse(res.body)
end

function janovixPost(string $path, array $body): array {
    global $baseUrl, $apiKey;
    $ch = curl_init("{$baseUrl}{$path}");
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_POST           => true,
        CURLOPT_POSTFIELDS     => json_encode($body),
        CURLOPT_HTTPHEADER     => [
            "Authorization: Bearer {$apiKey}",
            "Content-Type: application/json",
        ],
    ]);
    $response = curl_exec($ch);
    curl_close($ch);
    return json_decode($response, true);
}

$client = janovixPost("/clients", [
    "personType"    => "PHYSICAL",
    "firstName"     => "Juan",

    "dateOfBirth"   => "1980-01-01",

<Callout type="info">
	Al crear un cliente, la verificación en listas de vigilancia se activa
	automáticamente. Los campos `isPEP`, `ofacSanctioned`, `unscSanctioned` y
	`sat69bListed` se llenan de forma asíncrona. Consulta `GET /clients/:id` hasta
	que los valores se estabilicen, o revisa el cliente en la app AML (la interfaz
	escucha la finalización del watchlist). Los **webhooks** de screening aún no
	están disponibles — ver [Webhooks](/es/api/webhooks).
</Callout>

## Listar Clientes

```
GET /api/v1/clients?page=1&limit=20&kycStatus=INCOMPLETE
```

### Parámetros de Consulta

| Parámetro        | Tipo    | Descripción                                         |
| ---------------- | ------- | --------------------------------------------------- |
| `page`           | number  | Número de página (predeterminado: 1)                |
| `limit`          | number  | Elementos por página (máx. 100, predeterminado: 20) |
| `search`         | string  | Buscar por nombre o RFC                             |
| `kycStatus`      | string  | Filtrar por estado KYC                              |
| `personType`     | string  | Filtrar por `PHYSICAL`, `MORAL` o `TRUST`           |
| `isPEP`          | boolean | Filtrar clientes PEP                                |
| `ofacSanctioned` | boolean | Filtrar clientes sancionados por OFAC               |

## Obtener Estado KYC

```
GET /api/v1/clients/:id/kyc-status
```

Devuelve un desglose detallado del cumplimiento KYC, incluyendo qué secciones están completas, pendientes o faltantes:

```json
{
	"data": {
		"status": "INCOMPLETE",
		"completionPercentage": 45,
		"sections": {
			"personalInfo": "complete",
			"documents": "incomplete",
			"address": "complete",
			"shareholders": "not_applicable",
			"beneficialControllers": "not_applicable"
		},
		"missingFields": ["identityDocument", "taxDocument"]
	}
}
```
