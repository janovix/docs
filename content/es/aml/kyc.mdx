# KYC Autoservicio

La función de **KYC Autoservicio** te permite invitar a los clientes a completar sus propios datos KYC a través de un portal seguro protegido por token, eliminando la necesidad de que tu equipo capture manualmente la información del cliente en su nombre.

{/* IMAGE: public/images/aml/kyc-self-service-flow.png - Diagram of the full self-service KYC flow: compliance officer creates session → client receives email → client fills data → client submits → officer reviews → approve or reject */}

## Cómo Funciona

```
1. El oficial de cumplimiento crea una sesión KYC
   └─ El cliente recibe un correo de invitación con un enlace seguro

2. El cliente visita el portal de autoservicio
   ├─ Revisa y actualiza su información personal
   ├─ Sube documentos de identidad
   ├─ Agrega accionistas (si es persona moral)
   ├─ Agrega controladores beneficiarios
   └─ Envía para revisión

3. El sistema realiza automáticamente el escrutinio de los nuevos controladores beneficiarios

4. El oficial de cumplimiento revisa el envío
   ├─ Aprueba → el estado KYC del cliente se establece como COMPLETE
   └─ Rechaza → el cliente es notificado con el motivo y puede volver a enviar
```

## Modos de Autoservicio

Configura el modo en [Configuración → Cumplimiento](/es/settings/compliance):

| Modo        | Comportamiento                                                                     |
| ----------- | ---------------------------------------------------------------------------------- |
| `disabled`  | El autoservicio KYC está desactivado; todos los datos deben capturarse manualmente |
| `manual`    | Los oficiales de cumplimiento pueden crear sesiones bajo demanda                   |
| `automatic` | Se crea y envía automáticamente una sesión cuando se registra un nuevo cliente     |

## Crear una Sesión KYC

{/* IMAGE: public/images/aml/kyc-session-list.png - KYC session list showing client name, status badge, expiry date, and action buttons */}

<Steps>
### Buscar al Cliente
Navega a la página de detalle del cliente (**Clientes → [Nombre del Cliente]**) y desplázate a la sección **Sesiones KYC**.

### Crear Sesión

Haz clic en **Enviar Invitación KYC**. Janovix hará lo siguiente:

- Generará un token seguro único con expiración
- Enviará un correo de invitación a la dirección de correo registrada del cliente
- Creará un registro de sesión en estado `ACTIVE`

### Monitorear el Estado

Realiza un seguimiento del estado de la sesión en tiempo real:

| Estado           | Descripción                                                       |
| ---------------- | ----------------------------------------------------------------- |
| `ACTIVE`         | Sesión creada; correo enviado; el cliente aún no ha comenzado     |
| `IN_PROGRESS`    | El cliente abrió el enlace y comenzó a llenar los datos           |
| `SUBMITTED`      | El cliente envió el formulario; pendiente de revisión del oficial |
| `PENDING_REVIEW` | La revisión del oficial ha iniciado                               |
| `APPROVED`       | El oficial aprobó; el KYC del cliente se marcó como `COMPLETE`    |
| `REJECTED`       | El oficial rechazó con un motivo; el cliente puede ser reinvitado |
| `EXPIRED`        | El token de sesión expiró antes de que el cliente enviara         |
| `REVOKED`        | El oficial revocó manualmente la sesión                           |

### Reenviar si es Necesario

Si el cliente no ha respondido y la sesión sigue en estado `ACTIVE`, haz clic en **Reenviar Correo** para enviar una nueva invitación.

</Steps>

## La Experiencia del Cliente

{/* IMAGE: public/images/aml/kyc-client-view.png - What the client sees: the self-service portal with sections for personal info, documents, shareholders, and submit button */}

El cliente recibe un correo con un enlace al portal KYC de Janovix. El portal viene prellenado con los datos que tu equipo ya haya capturado. El cliente puede:

- **Revisar y corregir** información personal (nombre, RFC, domicilio)
- **Subir documentos** (identificación oficial, comprobante de domicilio, etc.)
- **Agregar accionistas** (para personas morales/fideicomisos)
- **Agregar controladores beneficiarios**
- **Enviar** el formulario completado

El portal es responsivo para dispositivos móviles y no requiere que el cliente cree una cuenta en Janovix. El acceso está controlado únicamente por el token de sesión.

<Callout type="info">
	**Expiración de sesión:** De manera predeterminada, las sesiones expiran
	después de **72 horas**. Puedes cambiar esto en [Configuración →
	Cumplimiento](/es/settings/compliance) mediante la configuración
	`selfServiceExpiryHours`.
</Callout>

## Revisión de un Envío

{/* IMAGE: public/images/aml/kyc-review.png - Compliance officer review screen showing submitted client data side-by-side with current records, with approve/reject buttons */}

Una vez que un cliente envía su sesión KYC (estado `SUBMITTED`), aparece una notificación en el feed de Alertas/notificaciones. Para revisar:

<Steps>
### Abrir la Sesión
Navega a **Sesiones KYC** (desde la lista de Clientes o desde la página de detalle del cliente) y haz clic en la sesión enviada.

### Revisar los Datos Enviados

La pantalla de revisión muestra:

- Todos los campos enviados lado a lado con los registros actuales (si existen)
- Documentos subidos disponibles para descarga/vista previa
- Resultados del escrutinio automático en listas de vigilancia para los nuevos controladores beneficiarios

### Tomar una Decisión

**Aprobar:** Haz clic en **Aprobar** — el estado KYC del cliente se actualiza a `COMPLETE`.

**Rechazar:** Haz clic en **Rechazar** y proporciona un motivo. El cliente recibe un correo con el motivo. Puedes crear una nueva sesión si el cliente necesita volver a enviar su información.

</Steps>

## Secciones Requeridas

Configura qué secciones son obligatorias para completar el autoservicio en [Configuración → Cumplimiento](/es/settings/compliance) mediante la configuración `selfServiceRequiredSections`. Las opciones incluyen:

- `personal_info`
- `documents`
- `address`
- `shareholders` (solo personas morales)
- `beneficial_controllers` (solo personas morales)

Una sesión solo puede enviarse cuando todas las secciones requeridas estén completadas.

## Bitácora de Auditoría de la Sesión

Cada acción sobre una sesión KYC se registra de forma inmutable en la bitácora de **Eventos**:

- Sesión creada
- Correo enviado / reenviado
- Cliente abrió el enlace
- Cada sección guardada
- Envío recibido
- Decisión de aprobación/rechazo con marca de tiempo y nombre del oficial

Esta bitácora de auditoría está disponible mediante `GET /api/v1/kyc-sessions/{id}/events` y es fundamental para las visitas de verificación de la SHCP.
