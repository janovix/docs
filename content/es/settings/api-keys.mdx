# Llaves de API

Las **Llaves de API** permiten que tus sistemas se autentiquen con la API de Janovix sin pasar por el flujo de inicio de sesión del usuario. Las llaves están vinculadas a tu organización y tienen los permisos del rol del usuario que las creó.

{/* IMAGE: public/images/settings/settings-api-keys.png - API keys list showing key name, masked value (sk_live_••••••••), creation date, last used date, and Rotate/Revoke actions */}

## Crear una Llave de API

{/* IMAGE: public/images/settings/settings-api-key-create.png - API key creation dialog showing name field, permissions summary, and Create button */}

<Steps>
### Abre la Página de Llaves de API
Navega a **Configuración → Llaves de API**.

### Haz Clic en Crear Llave

Ingresa un nombre descriptivo para la llave (p. ej., "Integración ERP", "Pipeline CI", "Sistema de Facturación"). Un buen nombre te ayuda a identificar qué sistema usa qué llave.

### Copia el Secreto

Después de crearla, **el valor completo de la llave se muestra solo una vez**. Cópialo de inmediato y guárdalo en tu gestor de secretos (p. ej., AWS Secrets Manager, HashiCorp Vault, Cloudflare Secrets).

El formato de la llave es: `sk_live_` seguido de una cadena aleatoria.

</Steps>

<Callout type="error">
	**Guarda tu llave de API de forma segura.** Janovix nunca vuelve a mostrar el
	valor completo de la llave después de su creación. Si pierdes la llave,
	deberás rotarla. Nunca incluyas llaves de API en repositorios de código
	fuente.
</Callout>

## Usar una Llave de API

Incluye la llave en el encabezado `Authorization` como token Bearer:

```http
Authorization: Bearer sk_live_your_api_key_here
```

Las llaves de API se autentican como la organización que las posee. Consulta [Autenticación de API](/es/api/authentication) para más detalles.

## Rotar una Llave

Si una llave pudo haber sido comprometida o deseas renovar las credenciales:

1. Haz clic en **Rotar** junto a la llave
2. Confirma la rotación
3. Se genera un nuevo valor secreto — cópialo de inmediato
4. El valor secreto anterior queda invalidado de inmediato

<Callout type="warning">
	Rotar una llave interrumpe de inmediato cualquier integración que use el valor
	anterior. Actualiza todos los consumidores antes de rotar en producción, o
	utiliza una ventana de mantenimiento.
</Callout>

## Revocar una Llave

Para eliminar una llave de forma permanente:

1. Haz clic en **Revocar** junto a la llave
2. Confirma

Las llaves revocadas no pueden recuperarse. Crea una nueva llave si es necesario.

## Buenas Prácticas

| Práctica                             | Recomendación                                                                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| **Una llave por integración**        | Usa llaves separadas para cada sistema. Así, revocar una llave no afecta sistemas no relacionados.                             |
| **Mínimo privilegio**                | Las llaves de API heredan el rol del usuario que las crea. No crees llaves con rol `owner` salvo que sea necesario.            |
| **Rota regularmente**                | Rota las llaves de API cada 90 días como práctica de higiene de seguridad.                                                     |
| **Monitorea el último uso**          | La lista muestra cuándo se usó por última vez cada llave. Revoca las llaves que no se hayan usado en más de 90 días.           |
| **Nunca en código del lado cliente** | Las llaves de API solo deben usarse en el servidor. Nunca las incluyas en JavaScript del navegador ni en aplicaciones móviles. |
