# Configuración de Cumplimiento AML

La sección de **Cumplimiento AML** es donde configuras la identidad regulatoria de tu organización — la información que determina los cálculos de umbrales, la generación de avisos al SAT y el comportamiento del autoservicio de KYC.

<Callout type="info">
	Esta página solo aparece en la barra lateral cuando la organización tiene
	**acceso al producto AML**. Las organizaciones solo Watchlist usan ajustes de
	Watchlist y cuenta sin este bloque.
</Callout>

## Configuración Requerida

Antes de registrar operaciones o generar avisos al SAT, **debes** completar la configuración de cumplimiento. La configuración incompleta bloqueará la generación de avisos.

### Clave del Sujeto Obligado (RFC)

| Campo                                               | Descripción                                                                                                                                     |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **RFC del Sujeto Obligado** (`obligatedSubjectKey`) | El RFC de 12 caracteres de tu organización registrado ante el SAT como _sujeto obligado_. Aparece en el encabezado de cada XML de aviso al SAT. |

<Callout type="error">
	Este RFC debe coincidir exactamente con tu registro ante el SAT. Un RFC
	incorrecto causará el rechazo de los avisos en el portal del SAT.
</Callout>

### Código de Actividad

| Campo                                   | Descripción                                                                                                                                                |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Código de Actividad** (`activityKey`) | El código de fracción del Art. 17 correspondiente a tu actividad vulnerable principal (p. ej., `VEH` para compraventa de vehículos, `INM` para inmuebles). |

El código de actividad determina:

- Qué umbrales de UMA se aplican a tus operaciones
- La variante de formato XML usada para los avisos al SAT
- Las reglas de alerta predeterminadas aplicadas a las nuevas operaciones

Si tu organización realiza **múltiples actividades vulnerables**, configura la principal aquí. Puedes registrar operaciones bajo cualquiera de los 20 códigos de actividad independientemente de esta configuración — afecta principalmente la presentación de avisos al SAT.

## Configuración del Autoservicio KYC

### Modo de Autoservicio

| Configuración | Descripción                                                                                                          |
| ------------- | -------------------------------------------------------------------------------------------------------------------- |
| `disabled`    | El autoservicio KYC está desactivado. Todos los datos del cliente deben ser ingresados manualmente por tu equipo.    |
| `manual`      | Tus oficiales de cumplimiento pueden crear sesiones KYC bajo demanda para clientes individuales.                     |
| `automatic`   | Se crea automáticamente una sesión KYC y se envía el correo de invitación cada vez que se registra un nuevo cliente. |

También puedes controlar si se envían **correos de invitación** para sesiones de autoservicio (interruptor junto al modo), según la configuración de correo.

### Expiración de la Sesión (Horas)

Define cuántas horas permanece válido el enlace de una sesión KYC antes de expirar. El cliente debe completar y enviar su KYC dentro de esta ventana.

**Predeterminado:** 72 horas (3 días)
**Mínimo:** 24 horas
**Máximo:** 720 horas (30 días)

### Secciones Requeridas

Configura qué secciones del formulario KYC deben completar los clientes antes de que se les permita enviarlo. Secciones disponibles:

| Clave de Sección         | Descripción                                                                      |
| ------------------------ | -------------------------------------------------------------------------------- |
| `personal_info`          | Datos básicos de identificación (nombre, RFC, fecha de nacimiento, nacionalidad) |
| `documents`              | Al menos un documento de identidad cargado                                       |
| `address`                | Al menos un domicilio registrado                                                 |
| `shareholders`           | Estructura accionaria (recomendado para personas morales)                        |
| `beneficial_controllers` | Controladores beneficiarios / propietarios beneficiarios finales                 |

<Callout type="info">
	La LFPIORPI exige recopilar información sobre los controladores beneficiarios
	para personas morales y fideicomisos (Art. 18-III). Recomendamos incluir
	`beneficial_controllers` en tus secciones requeridas para estos tipos de
	clientes.
</Callout>

## Valores UMA

La página también muestra el **valor UMA** vigente para umbrales (actualización anual, p. ej. **$117.31 MXN/día** en 2026). Para añadir o anular filas anuales, contacta al administrador (API `POST /api/v1/uma-values`).

## Guardar tu Configuración

Haz clic en **Guardar** después de realizar cambios. La configuración tiene efecto inmediato para las nuevas operaciones. Los registros existentes no se ven afectados de manera retroactiva.
