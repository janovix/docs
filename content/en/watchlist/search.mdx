# Running a Search

{/* IMAGE: public/images/watchlist/watchlist-search.png - Search interface showing name input field, dataset filter checkboxes (OFAC/UNSC/SAT69B/PEP/Adverse Media), and entity type selector */}

## Basic search

<Steps>
### Choose Individual vs Company

Use the **entity type** switch so the form asks for the right **date field** — date of birth for individuals, date of incorporation for organizations.

### Enter a name

Type the full name (or business name). Names are normalized (e.g. uppercased) for matching. The UI requires more than a **3-character** query before submit to avoid noisy searches.

For best results:

- Include the full legal name as it appears on official documents
- For physical persons: `APELLIDO PATERNO APELLIDO MATERNO Nombre(s)`
- For companies: Use the complete business name (_razón social_)

### Advanced options (optional)

Open **Advanced** to refine the search:

- **Identifiers** — comma-separated IDs (passport, RFC, etc.) for higher precision
- **Countries** — multi-select nationality / jurisdiction filters
- **Dates** — birth date (person) or incorporation date (company), depending on entity type

The home screen uses a **fixed similarity threshold (0.875)** in the product — you do not tune it per search from the main form.

### Select datasets (optional)

By default, all datasets are searched. Uncheck any you don't need to speed up results:

- OFAC SDN
- UNSC
- SAT 69-B
- PEP
- Adverse Media

Availability of PEP / adverse media blocks can also depend on **organization feature flags**.

### Run the search

Click **Search** or press Enter. Synchronous results (OFAC, UNSC, SAT 69-B) return first. **PEP** and **Adverse Media** may complete asynchronously and stream progress via **SSE** while you stay on the results route.

</Steps>

## First-time tour

On your first visit, a short **guided tour** (driver.js) highlights the entity switch, search field, advanced panel, and submit button. Dismiss it once; completion is stored in **localStorage**.

## Recent searches

The home page lists your **last five** queries for quick re-open.

## Session handoff

After you submit, the app stores lightweight state in **sessionStorage** so the **query detail** page can paint instantly while the network fetch completes.

## Identifier Search

For higher-confidence matching, search by a specific identifier instead of a name:

| Identifier Type | Example                 |
| --------------- | ----------------------- |
| Passport        | `A1234567`              |
| RFC (Mexico)    | `XAXX010101000`         |
| NIT (Colombia)  | `900123456`             |
| OFAC ID         | Numeric OFAC identifier |

Identifier searches perform **exact matching** and return matches immediately.

## Understanding Results

{/* IMAGE: public/images/watchlist/watchlist-results.png - Search results page showing match cards with entity name, database badge, match score percentage, and brief details */}

Each search result shows:

| Field           | Description                                                                 |
| --------------- | --------------------------------------------------------------------------- |
| **Match Score** | Overall confidence score (0–100%)                                           |
| **Database**    | Which list the match is from (OFAC SDN, UNSC, SAT 69-B, PEP, Adverse Media) |
| **Entity Name** | The name on the list                                                        |
| **Entity Type** | Individual or organization                                                  |
| **Country**     | Nationality or registered country                                           |
| **Status**      | Active sanction, designation status, or SAT 69-B phase                      |

### Score Breakdown

{/* IMAGE: public/images/watchlist/watchlist-result-detail.png - Expanded result card showing score breakdown: vector score, name similarity score, metadata score, identifier match indicator */}

Expand any result to see the **score components**:

| Score Component      | What It Measures                                                      |
| -------------------- | --------------------------------------------------------------------- |
| **Name score**       | Jaro-Winkler name similarity between query and matched name           |
| **Vector score**     | Semantic similarity (Cloudflare Vectorize + AI embeddings)            |
| **Metadata score**   | Match quality on additional fields (country, nationality, birth date) |
| **Identifier match** | Boolean — exact identifier match found (overrides score thresholds)   |

### Score Interpretation

| Score Range | Recommendation                                              |
| ----------- | ----------------------------------------------------------- |
| 90–100%     | High confidence match — requires immediate review           |
| 70–89%      | Probable match — review the details before proceeding       |
| 50–69%      | Possible match — may be a name coincidence; review context  |
| < 50%       | Low confidence — likely not the same person, but log review |

<Callout type="error">
	**Never proceed with a transaction for a 90%+ match without a documented
	review.** Even if you determine it's a false positive, the decision and
	rationale must be logged. The query history in Janovix serves as this record.
</Callout>

## Asynchronous Results (PEP and Adverse Media)

PEP and Adverse Media searches run on AI-powered containers and may take 10–60 seconds to return results. While they process:

- A loading indicator appears next to the PEP and Adverse Media sections
- Results stream in via Server-Sent Events as they arrive
- You can leave the page — results are saved to your [Query History](/en/watchlist/query-history) and available when you return

## Acting on a Match

When a match is found:

1. **Review the full entity details** — aliases, dates, identifiers, address, reason for listing
2. **Determine if it is the same person/entity** as your client (false positives are common with common names)
3. **Document your conclusion** in your internal compliance notes
4. If confirmed: do not proceed with the transaction; escalate per your internal AML policy
5. If a false positive: record this in your query notes for the audit trail
