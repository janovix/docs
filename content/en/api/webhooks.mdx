# Webhooks

Webhooks allow your systems to receive real-time notifications when events occur in Janovix, without polling the API. You register an HTTPS endpoint, and Janovix sends a `POST` request to it whenever a subscribed event fires.

## Event Types

| Event                                 | Trigger                                                |
| ------------------------------------- | ------------------------------------------------------ |
| `client.created`                      | A new client was registered                            |
| `client.updated`                      | A client's data was modified                           |
| `client.kyc_status_changed`           | A client's KYC status changed                          |
| `client.watchlist_screening_complete` | Watchlist screening results are ready                  |
| `operation.created`                   | A new operation was recorded                           |
| `alert.created`                       | A new alert was generated                              |
| `alert.status_changed`                | An alert's status changed (e.g., cancelled, submitted) |
| `notice.generated`                    | A SAT notice XML was generated                         |
| `notice.submitted`                    | A notice was marked as submitted                       |
| `kyc_session.submitted`               | A client submitted their KYC self-service form         |
| `kyc_session.status_changed`          | A KYC session was approved or rejected                 |

## Managing Webhook Endpoints

Endpoints are scoped to a specific **environment** (production, staging, or development). Events triggered in one environment are only delivered to endpoints registered in that same environment.

### Create an Endpoint

```http
POST https://api.janovix.com/api/v1/webhooks/endpoints
Authorization: Bearer jnvx_live_your_api_key_here
Content-Type: application/json

{
  "url": "https://your-server.com/webhooks/janovix",
  "events": ["client.created", "alert.created"],
  "description": "Production alert handler"
}
```

### List Endpoints

```http
GET https://api.janovix.com/api/v1/webhooks/endpoints
Authorization: Bearer jnvx_live_your_api_key_here
```

### Get an Endpoint

```http
GET https://api.janovix.com/api/v1/webhooks/endpoints/:id
Authorization: Bearer jnvx_live_your_api_key_here
```

### Update an Endpoint

```http
PUT https://api.janovix.com/api/v1/webhooks/endpoints/:id
Authorization: Bearer jnvx_live_your_api_key_here
Content-Type: application/json

{
  "url": "https://your-server.com/webhooks/janovix-v2",

```

### Delete an Endpoint

```http
DELETE https://api.janovix.com/api/v1/webhooks/endpoints/:id

```

Inspect delivery attempts for your organization. Useful for debugging failed deliveries.

```http
GET https://api.janovix.com/api/v1/webhooks/deliveries
Authorization: Bearer jnvx_live_your_api_key_here
```

Trigger a synthetic event to verify your endpoint is reachable and correctly processing payloads.

```http

Authorization: Bearer jnvx_live_your_api_key_here

  "endpointId": "wh_endpoint_01J...",
  "eventType": "client.created"
}
```

## Payload Format

All webhook payloads follow this structure:

```json
{
	"id": "evt_01J...",
	"type": "alert.created",
	"timestamp": "2025-07-16T10:05:00.000Z",
	"data": {
		// The full resource object
	}
}
```

| Field       | Type   | Description                                       |
| ----------- | ------ | ------------------------------------------------- |
| `id`        | string | Unique event identifier (idempotency key)         |
| `type`      | string | One of the event types listed above               |
| `timestamp` | string | ISO 8601 timestamp of when the event occurred     |
| `data`      | object | The full resource object that triggered the event |

## Signature Verification

Every webhook request includes two headers for verifying authenticity:

| Header                | Description                                           |
| --------------------- | ----------------------------------------------------- |
| `X-Janovix-Signature` | HMAC-SHA256 signature of the raw request body         |
| `X-Janovix-Timestamp` | Unix timestamp (seconds) of when the request was sent |

The signature is computed as `sha256=HMAC-SHA256(webhook_secret, timestamp.body)` where the timestamp and body are concatenated with a `.` separator.

<Callout type="warning">
	Always verify the signature before processing a webhook payload. Reject
	requests where the timestamp is more than 5 minutes old to prevent replay
	attacks.
</Callout>

<Tabs items={['TypeScript', 'Python', 'Node.js']}>
<Tabs.Tab>
```typescript
import crypto from "crypto";

function verifyWebhook(
body: string,
signature: string,
timestamp: string,
secret: string,
): boolean {
const age = Math.abs(Date.now() / 1000 - Number(timestamp));
if (age > 300) return false;

const expected = crypto
.createHmac("sha256", secret)
.update(`${timestamp}.${body}`)
.digest("hex");

return crypto.timingSafeEqual(
Buffer.from(signature),
Buffer.from(`sha256=${expected}`),
);
}

// In your request handler
const isValid = verifyWebhook(
rawBody,
req.headers["x-janovix-signature"],
req.headers["x-janovix-timestamp"],
process.env.WEBHOOK_SECRET,
);

````
</Tabs.Tab>
<Tabs.Tab>
```python
import hashlib
import hmac
import time

def verify_webhook(body: str, signature: str, timestamp: str, secret: str) -> bool:
    age = abs(time.time() - int(timestamp))
    if age > 300:
        return False

    expected = hmac.new(
        secret.encode(),
        f"{timestamp}.{body}".encode(),
        hashlib.sha256,
    ).hexdigest()

    return hmac.compare_digest(signature, f"sha256={expected}")
````

## Retry Behavior

If your endpoint returns a non-2xx status code or the request times out, Janovix retries delivery up to **3 attempts** with exponential backoff:

| Attempt | Delay        |
| ------- | ------------ |
| 1st     | Immediate    |
| 2nd     | ~30 seconds  |
| 3rd     | ~5 minutes   |

After all attempts are exhausted, the delivery is marked as failed. You can inspect failed deliveries via the `GET /api/v1/webhooks/deliveries` endpoint.

<Callout type="info">
  Your endpoint should return a `200` status code within 15 seconds. Offload
  heavy processing to a background queue and acknowledge the webhook
  immediately.
</Callout>

## SSE Streams (Alternative)

In addition to webhooks, several endpoints provide real-time updates via **Server-Sent Events (SSE)** for streaming use cases:

| Endpoint                                   | Description                              |
| ------------------------------------------ | ---------------------------------------- |
| `GET /api/v1/imports/:id/events`           | Real-time progress for a bulk import job |
| `GET /queries/:queryId/events` (Watchlist) | Async PEP and adverse media results      |

### SSE Example (TypeScript)

```typescript
const es = new EventSource(
  `https://api.janovix.com/api/v1/imports/${importId}/events`,
  {
    // EventSource doesn't support custom headers natively in browsers.
    // For server-side usage, use the `eventsource` npm package.
  },
);

es.addEventListener("progress", (e) => {
  const data = JSON.parse(e.data);
  console.log(`Progress: ${data.processedRows}/${data.totalRows}`);
});

es.addEventListener("complete", () => {
  console.log("Import complete");
  es.close();
});

es.addEventListener("error", (e) => {
  console.error("SSE error:", e);
  es.close();
});
````

### SSE Example (Python)

```python
import sseclient
import requests

def watch_import(import_id: str):
    response = session.get(
        f"{BASE_URL}/imports/{import_id}/events",
        stream=True,
        headers={"Accept": "text/event-stream"},
    )
    client = sseclient.SSEClient(response)
    for event in client.events():
        data = json.loads(event.data)
        if event.event == "complete":
            print("Import complete!")
            break
        print(f"Progress: {data.get('processedRows')}/{data.get('totalRows')}")
```
